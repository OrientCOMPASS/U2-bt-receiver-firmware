# v2 DELETED the six payload dirs under /system/vendor/operator/app/ and the
# device then hung at first boot (looping progress bar; v0/v1 with the
# payloads present boot fine) -- the MTK USP first-boot customization
# (com.mediatek.usp.CustomOperator in services.odex + the vendor-modified
# PackageInstaller) apparently never completes when the payload tree it
# walks is gone.

# v1-signed).  Same install flow, zero third-party code.  Side effect users
# may notice: six tiny entries in Settings -> Apps with no launcher icons;
# sideloading a real app with one of these package names later requires
# uninstalling the stub first (signature mismatch).
