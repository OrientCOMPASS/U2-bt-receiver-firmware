# debloat/remove-list.txt -- curated third-party preload removal list for the
# official KeenPlus U2 7.0 baseline (B04_35_1.5_8_3inch_M304_ST7701SN_20251016).
#
# Curated from the fw-probe run 40922183963 inventory (artifact
# fw-probe-report/apps_system.json, 95 APK records).  Policy: remove apps
# that are NEITHER AOSP platform NOR MediaTek BSP; keep everything else
# (see debloat/README.md for the full rationale and the keep-list).
#
# Paths are system-relative, top-level app dirs only
# (scripts/debloat_system.py enforces the shape).

# --- v1 (2026-10-30): the NETWORK DROPPER + cameraless cleanup ---
# ExactCalculator (com.android.calculator2): VENDOR-INJECTED silent app
# installer.  Evidence: its odex/dex references persist.sys.install.by.pwd
# (the gate prop set in the boot ramdisk default.prop) -- stock AOSP
# calculator contains no such code; probe v3b odex sweep (run 40934434361)
# found this string in NO other app.  This is the agent that, on the
# user's device after flashing debloat v0 with userdata wiped, silently
# installed Quark/Wandoujia/HiBy Music/万能联播/萌新社区 on first boot and
# uninstalled the stock Camera.  Platform-signed => holds INSTALL/DELETE
# _PACKAGES by signature.  Full dissection: probe v4 (calc_* artifacts).
app/ExactCalculator

# Camera (com.mediatek.camera): U2 has NO camera hardware (user-confirmed;

# MiraVision (com.mediatek.miravision.ui): display PQ-tuning UI, 60.8 MiB

# the HWC/SurfaceFlinger vendor stack and is untouched by removing the UI.
vendor/app/MiraVision

# --- v2 (2026-10-30): the OPERATOR PACK payload (the real dropper source) ---
# Probe v7 (run 40940965846) whole-image grep found the five apps the user
# saw installed on first boot hiding in /system/vendor/operator/app/ --
# a payload dir NO previous inventory covered (PackageManager never scans
# it; the v2 hidden-APK find excluded it via the */app/* filter).  Probe v8
# (run 40942885130) unrestricted *.apk sweep then caught a SIXTH payload
# app the name-list grep had missed: xunfeishurufa (iFlytek IME).
#
# Mechanism (probe v8 dissection): services.odex embeds the MTK USP
# framework -- com.mediatek.usp.CustomOperator with the literal path
# '/operator/app', installApk, enabledDisableApps and mOperatorAppInstallDir
# strings; the actual install goes through the VENDOR-MODIFIED
# PackageInstaller (its odex references persist.sys.install.by.pwd -- the
# gate prop that boot default.prop ships as =1 -- plus non-AOSP
# getBlockUninstallForUser/startPermsServiceForUninstall hooks).
# ValidationTools' autoInstallapk/AutoUninstallApkService classes (removed
# in v0) were the factory-line variant.  Nothing is downloaded: the APKs
# ship in the image and are installed locally on first boot.  Removing the
# payload kills the mechanism regardless of which installer runs it.
# vendor/operator holds nothing but these six app dirs (probe v8: configs
# file list empty, 203 MiB total).
#
# Keyboard note: removing the iFlytek IME payload is safe -- the stock AOSP
# LatinIME (com.android.inputmethod.latin) is present in app/LatinIME and
# is NOT touched by this list.
#
