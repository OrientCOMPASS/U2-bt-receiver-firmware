# Some basenames collide with unguarded AOSP 8.1 source modules
# (libion: system/core/libion; libtinyxml: external/tinyxml;
#  libpower: hardware/libhardware_legacy; libtinycompress:
#  external/tinycompress).  gen-vendor-mk.py RENAMES those prebuilts
# (<name>_u2) and keeps the original install filename via
# LOCAL_MODULE_STEM, so the MTK blobs are still what ends up in
# /system/lib -- see RENAMED in scripts/gen-vendor-mk.py.
# (libbt-vendor looks risky but every AOSP definer is guarded by
#  BOARD_HAVE_BLUETOOTH_* which u2 never sets -- verified on the tree.)
# libtinyalsa.so is NOT taken from the baseline at all: AOSP's own
# libtinyalsa is unavoidably installed on u2 (libbootanimation needs it)
# and two modules cannot own /system/lib/libtinyalsa.so.  The MTK audio
# HAL links against the classic tinyalsa C ABI, which AOSP 8.1 provides;
# device.mk adds libtinyalsa explicitly and the post-extraction dep scan
# verifies every UND tinyalsa symbol resolves.
# NOTE: the next four live in the baseline /system/lib (image path lib/),
# not /vendor/lib -- verified with debugfs against the stock image.

# ---- 64-bit runtime shim (decision D2, corrected) ----
# The baseline is a 64-bit product (ro.product.cpu.abi=arm64-v8a):
# /vendor/bin/wmt_loader, wmt_launcher and stp_dump3 are AArch64 even
# though every /vendor/lib blob is 32-bit.  u2 keeps a 32-bit system, but
# the arm64 kernel runs both ABIs, so the baseline 7.0 loader64 plus the
# exact lib64 closure of those three tools (readelf-verified: libc, libm,
# libdl, liblog, libc++, libcutils) is extracted here and installed to
# /system/bin/linker64 and /system/lib64/ via PRODUCT_COPY_FILES (see
# device.mk).  The 32-bit framework never loads these.

lib64/libc.so
lib64/libm.so
lib64/libdl.so
lib64/liblog.so
lib64/libc++.so
lib64/libcutils.so
